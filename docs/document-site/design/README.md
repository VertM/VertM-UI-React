## 贯穿全站的设计元素：列缘标记

选中态统一采用 **右缘 3px 金标**。这不是装饰，它来自组件的
「列缘状态」原则：内容在 vertical-lr 下自上而下推进，新列在右侧生长，
block-end 就是右缘，因此选中标记落在右缘。

同一根金标贯穿：logo 的金色 caret → 按钮选中态 → 瓦片脚注 → 左侧栏当前项 →
右 TOC 当前锚点 → 提示块。**别人看久了就能认出这是 VertM，而不需要读文字。**

**2026-10-10 决定：横排的文档站 chrome 也放右缘**，不按横排的逻辑轴（下边）走，
让"金标永远在右"成为识别特征。设计稿 03 里侧栏、TOC、提示块的金标画在左边，
以本条为准；现有 `site.css` 中对应三处的改法见 `handoff/README.md` §4.3。

### 缩放裁切规则

| 尺寸 | 处理 |
|------|------|
| ≥ 32px | 完整形态，三柱 + caret |
| 16–32px | 柱宽加粗到 5.5–7，caret 保留但加大 |
| < 16px | 舍弃 caret，只留三柱 |

纯几何形不靠细节点连接，因此缩放不会散——这是它相对文字标的天然优势。
**三档需分别出图，不要指望一套文件缩放到底。**

## 四个页型说明

### 01 首页

借鉴 antd 的**信息节奏**（Hero → 组件实物陈列 → 生态链接），不借鉴其视觉。

核心手法是**摆真实组件而非抽象图形**：Select（下拉自 block-end 展开）、
Menu（键盘按逻辑轴）、Calendar（日期列自右向左）——竖排蒙文的真实形态本身
就是最好的展示。

含控制菜单演示（9 套主题 + 2 种书写模式）与快速开始安装区。

### 02 组件总览

严格对齐 `ComponentsOverview.tsx` 与 `site.css` §13：

- 4 组 × 5 瓦片（通用 / 数据录入 / 导航 / 反馈）
- 标本用**组件级样式**：`.m.primary` / `.def` / `.tag` / `.field` / `.plain` / `.muted`
- `.m-rows` 多列形态（Icon / Form / Checkbox / Menu / Tabs / Steps / Pagination）
- 金标挂在带 `.s` 的那一列右侧 —— 所以 **Steps 的金标在第二列**（`.s` 是 ᠬᠣᠶᠠᠷ）
- Input 标本用描边框 + 金色 caret，暗示输入位置

**蒙文词全部取自源码**，不自造。修改时先读 `ComponentsOverview.tsx`。
但源码也会错：Pagination 标本用的是阿拉伯-印度数字 `١٢٣`，应为蒙古数字 `᠑᠒᠓`
（U+1811–U+1813）。源码已于 2026-10-10 修正，设计稿 02 仍是旧字符。

### 03 组件文档页

三栏：左导航（分组 + 当前项带金标）/ 正文 / 右 TOC。
DemoFrame 含灰点组、文件名、主题切换 chip、代码折叠条。
API 表：属性 / 类型 / 默认值 / 说明，类型与默认值用 JetBrains Mono。

页面已存在（46 页，由 dumi 从 `packages/react/src/*/index.md` 生成），
本稿是统一视觉的目标。稿内以下内容**不能照搬**：

- Button API 表是编造的：`verticalMarker` 属性不存在；`type` 实际为
  `primary / default / dashed / text / link`，`danger` 是独立布尔属性
- 左导航分组应取各页 frontmatter 的 `group.title`（通用 / 数据录入 / 导航 / 反馈 …）
- TOC 缺「键盘」，应插在「竖排提示」与「API」之间
- 侧栏、TOC、提示块的金标画在左边；站点已改到右缘（2026-10-10）
- 左导航灰底只铺到页面一半高

### 04 主题页

三段：语义色角色卡（6 个）→ 内置主题画廊（9 套）→ 自定义面板（色点 + 滑轨
+ 代码预览）。

稿内错误：第 6 张语义卡标为 Link，色值却是主色 `#0e2f74`；
6 张卡的说明文字全是"主按钮、选中态、caret"，是复制粘贴遗留。
